# TypeScript 디스코드 봇

discord.js v14 + TypeScript(ESM) 기반 봇. 커맨드 · 이벤트 · 컴포넌트를 **파일만 추가하면 자동으로 등록**되는 구조입니다.

- **[소원권 시스템](#소원권-시스템)** — 소원권/조각 관리, 소원 신청과 관리자 수락·거절
- **[별명 시스템](#별명-시스템)** — 서버 전체 별명을 한꺼번에 바꾸고 기간이 지나면 자동 복구
- **[채팅뻥](#채팅뻥)** — 이 채널에서 역할의 채팅을 막고 풀기
- **[타임아웃](#타임아웃)** — 정한 기간 동안 한 사람의 채팅·반응 막기
- **[타살버](#타살버)** — 타임아웃인데 살짝 약한 버전 (별명 · 깜빡이는 채팅 차단 · 반응 폭탄)
- **[출헉](#출헉)** — 하루 한 번 받아쓰기 출석 체크. 글자는 이미지로 내서 복붙을 막습니다
- **[서버 정보 · 프로필](#서버-정보--프로필)** — 서버와 유저에 대해 보여 줄 수 있는 것을 전부
- **[배포 자동화](RELEASE.md)** — 푸시하면 빌드·릴리스·디스코드 알림까지 자동 (`npm run ship`)
- 런타임 의존성은 둘 — discord.js 와 [@napi-rs/canvas](#출헉) (출헉 글자를 이미지로 그리는 데만 씁니다).
  `.env` 도 DB 도 Node 기본 기능으로 해결합니다
- 봇의 모든 출력이 [단일 렌더러](#출력-형식-규칙)를 지나 Components V2 · 색상 · 순서 · footer 규칙이 항상 지켜짐
- 커맨드 하나가 터져도 봇이 죽지 않고, 사용자에게는 안내 메시지가 감

> 이전에 만들었던 인터랙션 쇼케이스(`/interaction`, `/ping` 등)는 [backup/interaction-showcase/](backup/interaction-showcase) 에 그대로 보관돼 있습니다. 되살리려면 `src/` 안으로 다시 옮기고 `npm run deploy` 하면 됩니다.

## 1. 봇 만들고 토큰 받기

1. https://discord.com/developers/applications 에서 **New Application**
2. **Bot** 탭 → `Reset Token` → 토큰 복사 (한 번만 보여줍니다)
3. **General Information** 탭 → `Application ID` 복사
4. 봇을 서버에 초대 — **Installation** 탭의 설치 링크를 쓰거나, 아래 URL 의 `<APPLICATION_ID>` 를 바꿔서 접속
   ```
   https://discord.com/oauth2/authorize?client_id=<APPLICATION_ID>&permissions=0&scope=bot+applications.commands
   ```
   `applications.commands` 스코프가 없으면 슬래시 커맨드가 보이지 않습니다.
5. 개발용 서버 ID 복사 — 디스코드 설정에서 개발자 모드를 켠 뒤 서버 이름 우클릭 → `서버 ID 복사`

## 2. 설정

```bash
npm install
```

`.env.example` 을 `.env` 로 복사하고 값을 채웁니다.

```bash
copy .env.example .env
```

| 변수 | 필수 | 설명 |
|------|------|------|
| `DISCORD_TOKEN` | ✅ | Bot 탭에서 받은 토큰 |
| `DISCORD_CLIENT_ID` | ✅ | Application ID |
| `DISCORD_GUILD_ID` | | 개발용 서버 ID. 있으면 그 서버에만 등록되어 **즉시 반영**. 비우면 글로벌 등록(반영까지 최대 1시간) |
| `LOG_LEVEL` | | `debug` \| `info`(기본) \| `warn` \| `error` |

> `.env` 는 `.gitignore` 에 들어 있습니다. 토큰이 노출되면 Developer Portal 에서 바로 `Reset Token` 하세요.

## 3. 실행

```bash
npm run deploy
```

```bash
npm run dev
```

`deploy` 로 슬래시 커맨드를 디스코드에 등록하고, `dev` 로 봇을 켭니다.
서버에서 `/소원권 패널` 을 입력해 보세요. 소원 기능을 쓰려면 관리자 패널 > **설정** 에서 전달 채널을 먼저 정해야 합니다.

| 스크립트 | 설명 |
|----------|------|
| `npm run dev` | 파일 저장 시 자동 재시작 (tsx watch) |
| `npm run deploy` | 슬래시 커맨드를 디스코드에 등록 |
| `npm run typecheck` | 타입 검사만 |
| `npm run build` | `dist/` 로 컴파일 |
| `npm start` | 빌드된 결과 실행 (배포용) |

**`npm run deploy` 는 언제 다시 실행하나요?** 커맨드를 새로 만들거나 이름·설명·옵션을 바꿨을 때만 하면 됩니다.
커맨드 내부 로직만 고쳤다면 봇 재시작(`dev` 는 자동)으로 충분합니다.

## 커맨드 추가하기

`src/commands/` 에 파일을 만들고 `defineCommand` 를 **default export** 하면 끝입니다.
하위 폴더로 카테고리를 나눠도 됩니다 (`src/commands/fun/hello.ts`).

```ts
// src/commands/hello.ts
import { SlashCommandBuilder } from "discord.js";

import { defineCommand } from "../types.js";

export default defineCommand({
  data: new SlashCommandBuilder()
    .setName("hello")
    .setDescription("인사합니다."),

  async execute(interaction) {
    await interaction.reply(`안녕하세요, ${interaction.user.displayName}님!`);
  },
});
```

그다음 `npm run deploy` 한 번.

알아 두면 좋은 것들:

- **3초 규칙** — 인터랙션은 3초 안에 응답해야 합니다. 오래 걸리는 작업은 먼저
  `await interaction.deferReply()` 로 "생각 중" 상태를 만들고, 끝나면 `interaction.editReply(...)`.
- **나만 보이는 응답** — `{ content: "...", flags: MessageFlags.Ephemeral }`
- **옵션 값** — `interaction.options.getString("name")` 등. `.setRequired(true)` 를 붙이지 않으면 `null` 이 올 수 있습니다.
- **커맨드 이름** 은 소문자만 됩니다. 한글 이름을 보이게 하려면 `.setNameLocalizations({ ko: "인사" })` 를 쓰세요.

## 이벤트 추가하기

`src/events/` 에 `defineEvent` 를 default export 하면 자동 연결됩니다. `execute` 의 인자 타입은 이벤트 이름에서 추론됩니다.

```ts
// src/events/guild-member-add.ts
import { Events } from "discord.js";

import { defineEvent } from "../types.js";

export default defineEvent({
  name: Events.GuildMemberAdd,
  execute(member) {
    console.log(`${member.user.tag} 입장`);
  },
});
```

`once: true` 를 넣으면 최초 1회만 실행됩니다.

## 출력 형식 규칙

봇의 모든 출력은 [src/ui/response.ts](src/ui/response.ts) 한 곳을 지납니다. 호출부에서 색이나 footer 를
직접 만들지 않기 때문에 형식이 어긋날 수가 없습니다.

| 규칙 | 구현 |
|------|------|
| 모든 출력은 Components V2 | 임베드는 쓰지 않습니다. 모든 페이로드에 `MessageFlags.IsComponentsV2` 가 붙습니다 |
| 모든 요소는 Container 안에 | `buildContainer()` 가 컨테이너 하나를 만들고, 그 안에만 무언가를 넣습니다 |
| 색상은 네 가지뿐 | `"success"`(초록 `#57F287`) · `"progress"`(노랑 `#FEE75C`) · `"failure"`(빨강 `#ED4245`) · `"info"`(파랑 `#5865F2`). [뜻은 아래](#색을-고르는-기준) |
| footer 에 명령어를 쓴 유저 | `-# @사용자명` 이 자동으로 붙음. **프로필 사진은 넣지 않는다** |
| 수량이 바뀌면 반드시 표기 | `balance` 에 [`formatBalanceChange()`](src/wish/format.ts) 결과를 넘기면 변동 칸에 자동 삽입 |
| 오류는 내용 안에 `코드` 로 | `error` 에 원본 오류를 넘기면 내용 바로 아래에 최대 3줄 ([errors.ts](src/errors.ts)) |
| 유저·역할은 항상 멘션 | `<@id>` / `<@&id>`. 이름을 글자로 적지 않습니다 (footer 만 예외) |
| 멘션은 알림을 보내지 않음 | 모든 페이로드에 `allowedMentions: { parse: [] }`. 표시는 그대로, 알림만 빠집니다 |
| 시각은 타임스탬프 마크다운 | [time.ts](src/time.ts) 의 `at()` · `countdown()` · `atWithCountdown()` 만 씁니다 |
| 끝나는 효과는 종료 안내 | 효과를 건 메시지에 **답장**으로. 모양은 [end-notice.ts](src/ui/end-notice.ts) 가 정합니다 |
| 결과만 적기 | 명령이 무엇을 하는지, 앞으로 무슨 일이 일어날지 설명하지 않습니다 |
| 대상은 한 번만 | 내용이 이미 대상을 말했으면 변동 칸에 또 적지 않습니다 |

```
소원권: 3장 → 4장          ← 소원권이 바뀐 경우에만
소원권 조각: 7개 → 2개      ← 조각이 바뀐 경우에만
```

### 색을 고르는 기준

| 색 | `status` | 언제 |
|----|----------|------|
| 초록 | `success` | 요청한 작업이 **끝났다** |
| 노랑 | `progress` | **온전히 끝나지 못했다** — 아직 도는 중 · 누군가의 처리를 기다림 · 중간에 취소됨 · 일부만 실패 |
| 빨강 | `failure` | **실패**했다 — 권한 없음, 수량 부족, 디스코드 오류. 전부 실패면 여기 |
| 파랑 | `info` | 아무것도 바꾸지 않고 **보여 주기만** 한다 (패널, 확인, 랭킹, 종료 안내) |

노랑이 세 가지를 겸합니다. 「끝났다/안 끝났다/망했다」로 나누면 취소와 일부 실패가 갈 곳이
없어서, 노랑을 **온전히 끝나지 못한 것** 전부로 씁니다 — 별명 진행 중, 뚜따이 취소됨,
120명 중 2명 실패가 모두 노랑입니다.

### 응답 순서

컨테이너 안의 순서는 [`buildContainer()`](src/ui/response.ts) 가 정하고, 호출부는 재료만 넘깁니다.
가로줄(Separator)로만 구역을 나눕니다 — 없는 구역의 가로줄은 아예 그리지 않습니다.

```
┌───────────────────────────────────
│ ### 제목                ← 명령어 이름
│
│ 내용                     ← 유저·역할은 <@id> / <@&id> 멘션
│                            시각은 <t:초:F> / <t:초:R> 타임스탬프
│ `Error: …`               ← 오류가 있으면 최대 3줄
│
│ **변동**                ← 권한, 소원권 갯수 …
│ 허용 → **차단**
│ ───────────────────    ← 이미지가 있을 때만
│ [이미지 묶음]            ← MediaGallery (최대 10장)
│ [파일 카드]              ← File 컴포넌트
│ ───────────────────    ← 인터랙션이 있을 때만
│ [버튼] [드롭다운]
│ ───────────────────
│ -# @사용자명
└───────────────────────────────────
```

제목·내용·변동은 TextDisplay **하나**로 합쳐서 넣습니다. 셋을 따로 넣으면 줄간격이 벌어져
가로줄 없이도 칸이 나뉘어 보이기 때문입니다.

제목 오른쪽 끝에 버튼을 붙이려면 `accessoryButton` 을 넘깁니다 — 액션 로우는 항상 한 줄을
통째로 차지하므로, `Section` 의 액세서리로 넣는 것이 유일한 방법입니다.

### 결과만 적습니다

응답은 **무슨 일이 일어났는지**만 적습니다. 명령이 무엇을 하는 명령인지, 앞으로 무슨 일이
벌어질지는 적지 않습니다 — 그건 명령어 설명이 할 일이고, 매번 붙으면 읽을 게 늘어납니다.

```
안 함                              함
### 타살버 — 적용                  ### 타살버 — 적용
@마이즌 님에게 10분 동안 …          @마이즌 님에게 10분 동안 …

**걸린 것**                        **풀리는 시각**
별명이 `타살버맞` 으로 바뀝니다.     2026년 7월 27일 오후 10시 40분 (10분 후)
채팅이 2초 막혔다 5초 풀렸다 …
보내는 메시지마다 반응이 …
```

다른 칸이 이미 말한 것도 다시 적지 않습니다 — 환불했다는 안내는 변동 문구
(`소원권: 0장 → 1장`)가 이미 말하고 있습니다.

**실패한 이유는 적습니다.** 그건 설명이 아니라 결과입니다.

### 대상은 한 번만 적습니다

내용이 이미 대상을 말했으면 변동 칸에 또 두지 않습니다.

```
안 함                              함
@마이즌 님을 타임아웃했습니다.       @마이즌 님을 타임아웃했습니다.

**대상**                           **풀리는 시각**
@마이즌                            없음 → **… (1일 후)**
**풀리는 시각**
없음 → **… (1일 후)**
```

**내용이 대상을 말하지 않을 때만 칸으로 둡니다.** 실패 응답이 그렇습니다 — 내용이
「관리자 권한이 있는 사람은 타임아웃할 수 없습니다」 같은 **이유**라서, 누구 얘기인지는
칸이 말해 줘야 합니다.

### 끝나는 효과의 종료 안내

뚜따이 기간, 타임아웃처럼 **나중에 저절로 풀리는** 것은 끝날 때 안내를 한 번 남깁니다.
안내는 **그 효과를 건 메시지에 답장**으로 달립니다 — 무엇이 끝난 건지 거슬러 올라가 볼 수 있습니다.

모양은 [end-notice.ts](src/ui/end-notice.ts) 한곳에서 정합니다. 시스템마다 다르게 생기면
읽는 사람이 매번 다시 읽어야 하기 때문입니다.

```
┌ (파랑) ──────────────────────────────────────
│ ### <효과> — 기간 만료          ← 또는 「— 해제」
│ @마이즌 님의 **타임아웃** 효과가 끝났습니다.
│
│ **풀린 시각**                   ← 중간에 풀렸으면 **원래 풀릴 시각**
│ 2026년 7월 27일 오후 10시 40분 (방금)
│ **집계**                        ← 뒷정리가 있었을 때만
│ 전체 120명 · 완료 119명 · 실패 1명
│ ─────────────────────────────────────────────
│ -# @효과를 건 사람
└─────────────────────────────────────────────
```

| | |
|---|---|
| 색 | **파랑(정보)** 이 기본 — 아무도 요청하지 않은 알림성 응답입니다 |
| | 뒷정리가 일부 실패하면 노랑, 전부 실패하면 빨강 |
| 제목 | `<효과> — 기간 만료` / `<효과> — 해제` |
| 내용 | `<대상>의 **<효과>** 효과가 …` — 대상이 사람이면 「님의」, 서버 전원이면 「의」 |
| 시각 | 타임스탬프 마크다운. 만료면 「풀린 시각」, 중간 해제면 「원래 풀릴 시각」 |
| 집계 | 뒷정리가 있었을 때만 |
| footer | 효과를 **건** 사람 (푼 사람이 아니라) |

대상은 내용이 이미 말하므로 칸을 따로 두지 않습니다. 효과 이름 뒤에 「효과」를 붙이는 것은
조사 때문입니다 — `뚜따이이(가)` 같은 게 나오지 않습니다.

**푼 사람이 봇이면 이름을 적지 않습니다.** 「@봇 님이 풀었습니다」 는 아무 정보도 주지
않으므로 그냥 「풀렸습니다」 로 나갑니다. 감사 로그에서 푼 사람을 못 찾은 경우도 마찬가지입니다.

답장이 원본 작성자를 계속 울리지 않도록 `allowedMentions` 에 `repliedUser: false` 가 들어갑니다.

### 안내를 못 다는 경우

효과는 이미 끝났으므로 **안내 실패가 동작을 막지 않습니다.** 할 수 있는 만큼만 하고 로그를 남깁니다.

| 상황 | 어떻게 |
|------|--------|
| 효과를 건 메시지가 지워짐 | 답장을 포기하고 채널에 그냥 남깁니다 |
| 메시지 id 를 못 챙김 (응답 조회 실패) | 처음부터 채널에 남깁니다 |
| 채널이 지워졌거나 봇이 못 봄 | 아무것도 하지 않습니다 |
| 봇이 그 채널에 글을 못 씀 | 아무것도 하지 않습니다 |
| 대상이 서버를 떠남 | 그래도 안내합니다. 본문에 _(서버를 떠난 사람입니다)_ 를 붙입니다 |
| 봇이 서버에서 쫓겨남 | 서버 조회에 실패하므로 조용히 넘어갑니다 |
| 봇이 꺼져 있는 동안 끝남 | 켜질 때 안내합니다. 시각이 타임스탬프라 늦게 떠도 말이 됩니다 |

### 오류 표시

오류가 나면 사용자에게도 짧은 원인을 보여 줍니다. 어디서 막혔는지 바로 알 수 있어서
로그를 열어 보지 않아도 대충 짐작이 됩니다. 오류는 **내용 안**에 들어갑니다 — 변동 칸이 아닙니다.

```
┌ (빨강) ─────────────────────────────────────
│ ### 처리 중 문제가 생겼어요
│ 잠시 후 다시 시도해 주세요. …
│ `DiscordAPIError[50035]: Invalid Form Body`
│ ───────────────────────────────────────────
│ -# @사용자명
└────────────────────────────────────────────
```

호출부는 **원본 오류를 그대로** `error` 에 넘깁니다. 문구를 다듬는 것은 렌더러의 일입니다.

```ts
await interaction.editReply(
  editResponse({ status: "failure", title: "채팅뻥 실패", error, user: interaction.user }),
);
```

[describeError()](src/errors.ts) 는 **메시지만** 뽑습니다 — 스택 트레이스와 요청 URL 에는
인터랙션 토큰이 섞여 있어서 채널에 남기면 안 됩니다. 전체 내용은 로그에만 남습니다.

- **최대 3줄** · 최대 300자. 넘치는 부분은 `...` 으로 줄입니다
- 줄마다 인라인 코드로 감쌉니다. 코드블록(```` ``` ````)은 컨테이너에서 여백이 너무 커집니다
- 메시지에 ```` ``` ```` 가 섞여 있으면 형식이 깨지지 않게 바꿉니다

> **footer 에 프로필 사진을 넣지 마세요.** Components V2 에는 임베드 footer 같은 작은 아이콘 자리가
> 없습니다 — 이미지 프리미티브가 `Thumbnail`(Section 액세서리)과 `MediaGallery` 뿐인데
> 둘 다 크기 지정이 안 되고 본문만큼 크게 그려집니다. 그래서 이름만 씁니다.

> **Components V2 메시지에는 `content` 도 `embeds` 도 실을 수 없습니다.** 렌더러가 `components` 와
> `flags` 만 돌려주는 이유입니다. 여기에 `content` 를 얹으면 디스코드가 400 으로 거부합니다.

> **메시지의 Components V2 여부는 만들 때 정해지고 나중에 못 바꿉니다.** 이 규칙을 정하기 전에
> 올라간 임베드 메시지(예: 처리 대기 중인 소원)는 컨테이너로 갈아 끼울 수 없습니다.
> `message.flags.has(IsComponentsV2)` 로 갈라서, 옛 메시지는 `components` 만 바꿉니다
> ([components/wish.ts](src/components/wish.ts) 의 `decideWish`).

## 시간 입력과 시간 출력

시간을 받는 모든 입력란은 같은 형식을 씁니다. **일 · 시간 · 분 · 초** 로 적고,
**단위를 안 쓰면 초**로 봅니다. 구현은 [src/time.ts](src/time.ts) 한 곳뿐입니다.

| 입력 | 뜻 |
|------|-----|
| `1일 4시간 45초` | 100,845초 |
| `64` | 64초 (= 1분 4초) |
| `1일4시간45초` | 공백 없이 붙여 써도 됩니다 |
| `45초 1일 4시간` | 순서가 섞여도 합산합니다 |
| `1d 2h 3m 4s` | 영문 약어도 받습니다 |
| `1분 30` | 단위 없는 값만 초로 — 90초 |

알 수 없는 글자가 섞이면 **조용히 무시하지 않고 형식 오류**로 돌려줍니다.
`1일 4시간` 을 `1일 4시` 로 잘못 읽어 엉뚱한 시각에 풀리는 것이 더 나쁘기 때문입니다.
최대 365일까지 받습니다.

**출력** — 봇이 내보내는 모든 시각과 카운트다운은 디스코드 **타임스탬프 마크다운**을 씁니다.
보는 사람의 시간대로 표시되고, 남은 시간은 디스코드가 알아서 갱신해 줍니다.

```
<t:1800000000:F>   2027년 1월 15일 오후 6시 40분     at()
<t:1800000000:R>   3시간 후 / 5분 전                 countdown()
```

문자열로 날짜를 직접 조립하지 마세요 — `atWithCountdown()` 이 둘을 함께 냅니다.
[출력 형식 규칙](#출력-형식-규칙)의 일부라, `toLocaleString()` 같은 걸 쓰면 검사에서 걸립니다.

`formatDuration()` 은 예외입니다. 이건 **시각이 아니라 길이**(`1일 4시간 45초`)라서
타임스탬프로 표현할 수 없습니다. 사용자가 입력한 기간을 그대로 되돌려 줄 때만 쓰고,
"언제 풀리는지"는 반드시 `atWithCountdown()` 으로 냅니다.

## 별명 시스템

서버 전체의 별명을 한꺼번에 바꿉니다. **별명 관리(Manage Nicknames)** 권한이 있는 사람만 쓸 수 있고,
디스코드 쪽에서도 권한 없는 사람에게는 명령 자체가 보이지 않습니다.

```
/별명 뚜따이 별명:요땅그래
/별명 뚜따이 별명:요땅그래 유저:@마이즌 기간:1일 4시간
/별명 바사삭
/별명 바사삭 유저:@마이즌
```

| 하위 명령 | 동작 |
|-----------|------|
| 뚜따이 | 별명을 정한 값으로 바꿉니다 |
| 바사삭 | 별명을 **지웁니다**. 예전 별명을 저장해 되돌리는 게 아니라, 별명을 없애면 사용자명으로 돌아가는 디스코드 동작을 그대로 씁니다 |

| 옵션 | 뚜따이 | 바사삭 | 설명 |
|------|:------:|:------:|------|
| `별명` | ✅ 필수 | — | 바꿀 별명 (32자까지) |
| `유저` | 선택 | 선택 | **지목한 한 사람만** 바꿉니다. 비우면 서버 전원 |
| `기간` | 선택 | — | 지나면 **자동으로 바사삭**됩니다. 비우면 직접 풀 때까지 유지 |

> 슬래시 커맨드 옵션은 한 명만 고를 수 있습니다. 여러 명을 한 칸에 적는 방식(문자열 + 자동완성)도
> 만들어 봤지만 쓰기 불편해서 되돌렸습니다.
> 다만 내부(`targetIds`)는 목록으로 되어 있어, 나중에 여러 명이 필요해지면 넘기는 값만 늘리면 됩니다.

지목한 사람은 REST 로 가져옵니다 — 멤버 목록 요청 제한과 무관하고 즉시 끝납니다.
그래서 취소 버튼도 붙지 않고, 돌고 있는 전체 작업을 밀어내지도 않습니다.
서버를 나간 사람을 지목하면 그 사람만 「서버에 없는 사람」 으로 실패 처리하고 나머지는 진행합니다.

**자동 바사삭 예약은 대상별로 따로 잡힙니다.** 전원에게 1일짜리 뚜따이를 걸어 둔 상태에서
누군가에게 1시간짜리 개별 뚜따이를 걸어도 전체 예약이 사라지지 않습니다.
반대로 **전체 바사삭은** 모두의 별명을 지우므로 개별 예약까지 전부 정리하고,
**지목 바사삭은** 그 사람의 예약만 지웁니다.

### 실시간 진행률과 취소

큰 서버는 한참 걸리므로 같은 메시지를 계속 갈아 끼웁니다 (1.5초 간격 — 메시지 수정에도 요청 제한이 있습니다).

```
┌ (노랑) ────────────────────────────────────────
│ ### 뚜따이 진행 중                    [ 취소 ]  ← 제목 오른쪽
│ 모두의 별명을 `요땅그래` 로 바꿉니다.
│ **진행**
│ `████████░░░░░░░░`  39%
│ **집계**
│ 전체 120명 · 완료 45명 · 실패 2명
│ **자동 바사삭**
│ 2026년 7월 27일 오전 3시 12분 (10시간 후)
│ ──────────────────────────────────────────────
│ -# @사용자명
└───────────────────────────────────────────────
```

> 버튼을 **제목 오른쪽 끝**에 붙이려면 `Section` 의 **액세서리**로 넣어야 합니다
> (`accessoryButton`). 액션 로우는 항상 한 줄을 통째로 차지해서 저 자리에 못 옵니다.
>
> 버튼과 취소 버튼이 모두 컨테이너 안에 들어가고, 색상·순서·footer 규칙은 다른 출력과 똑같습니다.
> 컨테이너 속성은 메시지를 만들 때 정해지므로 `deferReply()` 가 아니라 바로 `reply()` 로 답하고,
> 그래서 「준비 중」 화면이 먼저 뜹니다.

### 겹치면 나중 것이 이깁니다

서버마다 별명 작업은 **하나만** 돕니다. 뚜따이 도중에 바사삭이 시작되면(또는 반대로)
먼저 돌던 쪽을 취소하고, **완전히 멈춘 뒤**에 새 작업이 시작됩니다.
기다리지 않으면 두 루프가 같은 사람의 별명을 번갈아 바꿔 결과를 알 수 없게 됩니다.

취소되면 그 작업의 메시지가 「취소됨」으로 바뀌고 어디까지 진행했는지 남습니다.
**이미 바뀐 사람은 되돌리지 않습니다** — 되돌리고 싶으면 바사삭을 쓰면 됩니다.

취소 버튼의 `customId` 에는 작업 id 가 들어 있어서, 이미 끝난 메시지의 버튼을 눌러도
그 뒤에 시작된 다른 작업이 죽지 않습니다.

끝나면 색이 바뀝니다 — 전부 성공 **초록**, 일부 실패 **노랑**, 전부 실패 **빨강**.

- 이미 같은 별명인 사람은 요청을 보내지 않고 **완료로 셉니다**. 큰 서버에서 눈에 띄게 빨라집니다
- 실패 원인은 화면에 늘어놓지 않고 **로그에만** 남깁니다 (`봇보다 높은 역할 (권한 부족) — 2명`)
- 봇 계정은 대상에서 제외합니다
- 인터랙션 토큰은 15분이면 만료되므로, 그보다 오래 걸리면 결과를 채널에 새 메시지로 남깁니다

### 멤버 목록 요청 제한

`guild.members.fetch()` 는 게이트웨이 opcode 8 을 쓰는데 제한이 빡빡합니다
(`GatewayRateLimitError: Request with opcode 8 was rate limited`). 세 겹으로 막았습니다.

1. **캐시 재사용** — `cache.size >= memberCount` 면 게이트웨이에 아예 묻지 않습니다.
   뚜따이 직후 바사삭처럼 연달아 실행할 때 걸리던 주된 원인이었습니다
2. **직렬화** — 프로세스 전체에서 멤버 목록 요청을 한 번에 하나만 보냅니다.
   여러 서버의 만료가 겹칠 때 동시에 요청해 걸리던 문제를 없앱니다
3. **재시도** — 걸리면 디스코드가 알려 준 `retry_after` 만큼 기다렸다 최대 4번까지 다시 시도합니다.
   자동 바사삭이 걸린 경우에는 상태를 지우지 않고 그 시간 뒤로 예약을 다시 잡습니다

### 바꿀 수 없는 사람

디스코드가 막는 경우라 오류가 아니라 정상입니다.

| 대상 | 이유 |
|------|------|
| 서버 소유자 | 누구도 소유자의 별명을 바꿀 수 없습니다 |
| 봇보다 높거나 같은 역할 | 역할 서열 규칙 |
| 전원 실패 | 봇 역할에 **별명 관리** 권한이 없는 것 — 시작 전에 미리 막고 안내합니다 |

몇 명이 왜 실패했는지는 봇 로그에서 확인할 수 있습니다.

### 기간 만료는 재시작을 견딥니다

만료 시각을 `data/nicknames.json` 에 저장하고, 부팅할 때 예약을 되살립니다
([scheduler.ts](src/nickname/scheduler.ts)). 봇이 꺼져 있는 동안 기간이 지났으면 켜질 때 바로 바사삭합니다.

`setTimeout` 은 약 24.8일까지만 감당하므로, 그보다 긴 기간은 잘라서 다시 예약합니다.

바사삭이 끝나면 [종료 안내](#끝나는-효과의-종료-안내)를 **뚜따이를 건 메시지에 답장**으로 남깁니다.
자동 바사삭이 일부 실패했으면 집계가 함께 나오고 색도 그에 맞게 바뀝니다.

## 채팅뻥

역할의 채팅을 **명령을 쓴 채널에서** 막거나 풉니다. 지금 상태를 읽어서 뒤집는 토글이라
같은 명령으로 되돌립니다.

```
/채팅뻥              ← 비우면 @everyone (이 채널 전체)
/채팅뻥 역할:@손님
```

**역할 관리(Manage Roles)** 권한이 필요합니다. 권한 없는 사람에게는 명령이 보이지 않습니다.

다른 채널을 막으려면 그 채널에서 명령을 다시 씁니다. 스레드에서 쓰면 **부모 채널**이 바뀝니다 —
스레드에는 자체 권한이 없고 부모 채널의 권한을 물려받기 때문입니다.

### 역할 권한이 아니라 채널 덮어쓰기를 씁니다

서버 권한은 가진 역할끼리 **더해집니다**. 그래서 `@손님` 의 「메시지 보내기」를 꺼도
`@everyone` 이 허용하는 동안에는 **아무 일도 일어나지 않습니다.**

```
@everyone : 메시지 보내기 허용
@손님      : 메시지 보내기 없음     →  허용 ∪ 없음 = 허용  (안 막힘)
```

채널 덮어쓰기의 **차단**은 역할 권한을 이깁니다. 그래서 이 채널에 그 역할의
「메시지 보내기」 차단을 걸었다 푸는 방식으로 동작합니다.

| | 하는 일 |
|---|---|
| 끄기 | 이 채널 덮어쓰기에 `SendMessages: 차단` 을 넣습니다 |
| 켜기 | 그 항목을 **빼서** 원래대로(상속) 되돌립니다. 명시적 허용으로 바꾸지 않습니다 |

같은 덮어쓰기의 다른 항목은 그대로 둡니다 — `permissionOverwrites.edit` 은 지정한 것만 손댑니다.

### 바꿀 수 없는 역할

| 대상 | 이유 |
|------|------|
| **관리자** 권한이 있는 역할 | 관리자는 채널 차단도 무시합니다. 조용히 실패하지 않도록 미리 막고 안내합니다 |
| 자신보다 높거나 같은 역할 | 서버 소유자는 예외입니다 |

이 채널에서 봇에게 **역할 관리** 권한이 없으면 시작 전에 안내하고 멈춥니다.

> 이 채널에서 `@everyone` 을 끄면 봇도 이 채널에 일반 메시지를 못 보내게 될 수 있습니다.
> (슬래시 커맨드 응답은 그와 무관하게 나가므로 다시 켜는 데는 지장이 없습니다)

역할은 **멘션**으로 적습니다 (`<@&id>`). 규칙상 유저든 역할이든 이름을 글자로 적지 않습니다.

멘션을 쓰면서도 알림이 가지 않는 이유는 렌더러가 모든 페이로드에
`allowedMentions: { parse: [] }` 를 붙이기 때문입니다 — 파란 칩으로 보이기만 하고 알림은 빠집니다.
`@everyone` 을 적어도 서버 전체에 알림이 가지 않습니다.

`@everyone` 만 `Role#toString()` 이 `<@&id>` 가 아니라 `@everyone` 문자열을 돌려줍니다.
이름을 직접 이어 붙이지 않으므로 예전의 `@@everyone` 문제도 구조적으로 사라졌습니다.

## 타임아웃

한 사람의 채팅과 반응을 정한 시각까지 막습니다. 디스코드 기본 기능이라 서버 어디서든 적용됩니다.

```
/타임아웃 유저:@마이즌 기간:1일 4시간
/타임아웃 유저:@마이즌 기간:64        ← 숫자만 쓰면 초 (= 1분 4초)
/타임아웃 유저:@마이즌               ← 기간을 비우면 해제
```

**멤버 타임아웃(Moderate Members)** 권한이 필요합니다. 기간은 [공용 시간 형식](#시간-입력과-시간-출력)을 씁니다.

풀리는 시각은 타임스탬프 마크다운으로 나옵니다 — 보는 사람의 시간대로 표시되고 남은 시간이 계속 갱신됩니다.

```
┌ (초록) ──────────────────────────────────────
│ ### 타임아웃 — 적용
│ @마이즌 님을 1일 4시간 동안 타임아웃했습니다.
│
│ **풀리는 시각**
│ 없음 → **2026년 7월 27일 오후 10시 40분 (1일 후)**
│ ─────────────────────────────────────────────
│ -# @사용자명
└─────────────────────────────────────────────
```

### 걸리는 한계

| 대상 | 이유 |
|------|------|
| 서버 소유자 | 디스코드가 막습니다 |
| **관리자** 권한이 있는 사람 | 타임아웃이 적용되지 않습니다 |
| 봇보다 높은 역할 | 서버 설정 > 역할 에서 봇 역할을 위로 올려야 합니다 |
| 자신보다 높거나 같은 역할 | 서버 소유자는 예외입니다 |

기간은 **최대 28일**입니다 — 디스코드의 한계입니다. 공용 파서는 365일까지 받으므로
이 명령이 따로 걸러서 안내합니다. 타임아웃이 안 걸린 사람을 해제하려 하면 실패로 알려 줍니다.

### 끝나면 한 번 더 알립니다

[끝나는 효과의 종료 안내](#끝나는-효과의-종료-안내) 규칙을 따릅니다 — 타임아웃을 건 메시지에
답장으로 안내가 달립니다. 뚜따이 기간 만료와 똑같이 생겼습니다.

끝나는 길이 셋인데, 각각 다른 곳이 맡습니다.

| 끝나는 방식 | 누가 알리나 |
|-------------|-------------|
| 기간이 다 됨 | [scheduler.ts](src/timeout/scheduler.ts) 의 예약 |
| `/타임아웃` 으로 해제 | 명령이 직접 — 푼 사람을 정확히 알기 때문 |
| 디스코드 화면에서 해제 | [guild-member-update.ts](src/events/guild-member-update.ts) 가 감사 로그에서 푼 사람을 찾음 (못 찾으면 이름 없이) |

> **`/타임아웃` 으로 풀면 `guildMemberUpdate` 도 같은 해제를 봅니다.** 그런데 감사 로그의
> 실행자는 명령을 쓴 사람이 아니라 **봇**입니다 — 실제로 API 를 부른 게 봇이니까요.
> 이벤트 쪽이 먼저 알리면 「봇이 풀었다」로 나갑니다.
>
> 그래서 두 겹으로 막습니다.
> ① 명령이 타임아웃 API 호출 **직후, 결과를 보여 주기 전에** 알립니다.
>    상태를 먼저 가져가므로(`takeState`) 이벤트 쪽은 아무것도 못 찾고 지나갑니다.
> ② 이벤트는 감사 로그 실행자가 봇이면 아예 넘어갑니다.

> **디스코드는 타임아웃이 저절로 풀릴 때 아무 이벤트도 보내지 않습니다.**
> `guildMemberUpdate` 는 사람이 직접 풀 때만 옵니다. 그래서 기간 만료는 직접 예약해 둡니다.

알림에 필요한 것(알릴 채널, 건 사람)은 디스코드가 알려 주지 않으므로 `data/timeouts.json` 에
따로 저장합니다. 봇을 재시작해도 예약이 되살아나고, 꺼져 있는 동안 끝난 것은 켜질 때 알립니다.

알림이 두 번 나가지 않게, 상태를 **읽으면서 동시에 지웁니다**(`takeState`). 예약된 타이머와
`guildMemberUpdate` 가 거의 같은 순간에 들어와도 먼저 가져간 쪽만 알립니다.

봇 밖에서 걸린 타임아웃은 저장된 게 없으므로 알리지 않습니다 — 어느 채널에 알릴지도 모르고,
남의 서버 운영까지 떠드는 건 시끄럽습니다.

## 타살버

**타**임아웃인데 **살**짝 약한 **버**전. 입을 완전히 막는 대신 성가시게 합니다.

```
/타살버 유저:@마이즌 기간:10분
/타살버 유저:@마이즌            ← 기간을 비우면 해제
```

**멤버 타임아웃(Moderate Members)** 권한이 필요합니다. 기간은 [공용 시간 형식](#시간-입력과-시간-출력)을 씁니다.

걸린 사람에게 일어나는 일:

| | |
|---|---|
| 별명 | `타살버맞` 으로 바뀝니다. 끝나면 **걸기 전 별명**으로 되돌립니다 |
| 채팅 | 차단 역할이 **2초 붙었다 5초 빠졌다** 반복합니다. 말은 되는데 자꾸 끊깁니다 |
| 반응 | 보내는 메시지마다 굴러가는 이모지가 **무작위 개수**로 달립니다 |

이 표는 문서에만 있습니다 — 응답에는 [결과만 적습니다](#결과만-적습니다).

### 역할만으로는 안 막힙니다

`/채팅뻥` 에서 겪은 것과 같습니다 — 서버 권한은 역할끼리 **더해지므로**, 「메시지 보내기」가
없는 역할을 붙여도 `@everyone` 이 허용하는 동안에는 아무 일도 일어나지 않습니다.

그래서 `타살버` 역할을 만든 뒤 **모든 채널에 그 역할의 「메시지 보내기」 차단**을 걸어 둡니다.
차단은 역할 권한을 이기므로 이때부터 역할을 붙이면 실제로 입이 막힙니다.

- 역할은 서버마다 **하나만** 만들고 id 를 기억해 재사용합니다
- 이미 차단이 걸린 채널은 건너뛰므로 두 번째부터는 요청이 거의 나가지 않습니다
- 누가 역할을 지우면 다음에 새로 만듭니다

### 기간은 최대 1일

7초마다 역할을 넣었다 뺐다 하므로 요청이 계속 나갑니다 — 하루면 약 1만 2천 번입니다.
그보다 길게 걸 이유가 없어서 상한을 뒀습니다.

### 별명 되돌리기

**걸기 전 별명을 저장해 둡니다.** 디스코드는 예전 값을 알려 주지 않기 때문입니다.
별명이 없던 사람은 `null` 로 기억했다가 별명을 지워 사용자명으로 되돌립니다.

> 이미 걸려 있는 사람에게 다시 걸면 기간만 늘어나고, **걸기 전 별명은 처음 것을 지킵니다.**
> 안 그러면 두 번째 실행에서 `타살버맞` 이 「원래 별명」으로 저장돼 영영 못 되돌립니다.

### 반응

이모지는 **이름으로** 찾습니다 — 봇이 들어가 있는 서버 전체에서 찾으므로, 이모지가 있는
서버에 봇이 들어가 있기만 하면 됩니다. 없는 이름은 조용히 건너뜁니다.

```
_cartwheel  _ccccccccc  _dol_li_gi_yup  _pcw
_personcartwheeling  _shuoooong  _wheelcart  _yup_dol_gi
```

개수는 1개부터 쓸 수 있는 전부까지 무작위이고, 순서도 섞습니다.
메시지 **내용은 읽지 않습니다** — 누가 보냈는지만 알면 되므로 특권 인텐트(MessageContent)가
필요 없고, `GuildMessages` 만 켜면 됩니다.

### 끝나면

[종료 안내](#끝나는-효과의-종료-안내)를 타살버를 건 메시지에 답장으로 남깁니다.
그 전에 반복을 멈추고 · 역할을 빼고 · 별명을 되돌립니다. 봇을 재시작해도 되살아나고,
꺼져 있는 동안 기간이 지났으면 켜질 때 정리합니다.

## 서버 정보 · 프로필

보여 주기만 하는 두 명령입니다. 권한 제한이 없어 누구나 쓸 수 있습니다.

```
/서ser버ber정jung보bow
/프로필쀼                ← 비우면 자신
/프로필쀼 유저:@마이즌
```

| | 보여 주는 것 |
|---|---|
| 서버 | 이름·id · 소유자 · 만든 날 · 멤버 수 · 채널 종류별 수 · 역할 수 · 이모지·스티커 수 · 부스트 · 보안 설정(인증·필터·2단계·NSFW) · 기본 알림 · 잠수/시스템/규칙 채널 · 맞춤 초대 · 언어 · 켜진 기능 · 설명 · 아이콘·배너 |
| 프로필 | 멘션·id · 사용자명 · 표시 이름 · 별명 · 계정 만든 날 · 서버 참가 · 부스트 시작 · 타임아웃 · 역할 · 최고 역할 · 주요 권한 · 아바타·배너 |

규칙을 그대로 따릅니다 — **시각은 전부 타임스탬프**(보는 사람 시간대로), 소유자·역할·채널은
**전부 멘션**, 색은 아무것도 바꾸지 않으므로 **파랑**입니다.

- **값이 없는 칸은 아예 만들지 않습니다.** 규칙 채널이 없으면 그 줄이 안 나옵니다
- 디스코드가 주는 값은 대부분 숫자 enum 이라 [format.ts](src/info/format.ts) 가 말로 바꿉니다.
  인증 단계 `2` 가 아니라 「중간 — 가입 5분 후」로 나옵니다
- 역할은 위에서부터 20개까지, 나머지는 「외 n개」로 줄입니다. 다 적으면 글자 수 한계를 넘습니다
- 권한은 `checkAdmin` 을 끄고 봅니다 — 안 그러면 관리자에게 전부 켜진 것으로 나옵니다

> **배너는 멤버 정보에 딸려 오지 않습니다.** 유저를 새로 받아야 나오므로 `/프로필쀼` 만
> `deferReply` 를 씁니다. 못 받아도 나머지는 그대로 보여 줍니다.

## 출헉

하루 한 번, 관리자가 올린 글자를 **받아 적어야** 출석이 됩니다.

```
/출헉체흐 텍스트:오늘도화이팅
```

**관리자만** 쓸 수 있고, 서버마다 **하루에 한 번**입니다. 올리면 채널에 이렇게 나갑니다.

```
┌ (파랑) ──────────────────────────────────────
│ ### 오늘의 출헉
│ ┌──────────────────────────┐
│ │  오늘도화이팅              │   ← 이미지. 긁어서 복사할 수 없습니다
│ └──────────────────────────┘
│ **제출많**
│ @마이즌 (12일)
│ ─────────────────────────────────────────────
│ [ 안녕난버튼이야 ]
│ ─────────────────────────────────────────────
│ -# @사용자명
└─────────────────────────────────────────────
```

버튼을 누르면 모달이 열리고, 이미지의 글자를 그대로 적으면 성공입니다.
성공 메시지는 **누른 사람에게만** 보입니다.

```
@마이즌 출헉 성공! (연속 3일째)
소원권 조각: 0개 → 1개          ← 4일마다
```

| | |
|---|---|
| 판정 | 앞뒤 공백만 봐 주고 나머지는 **그대로** 맞아야 합니다 |
| 보상 | **누적** 출헉일수가 4의 배수가 될 때마다 소원권 조각 1개 |
| 연속 | 어제 했으면 이어지고, 하루라도 빠지면 1부터 다시 셉니다 |
| 제출많 | 누적이 가장 많은 사람. 아직 아무도 없으면 칸이 나오지 않습니다 |
| 범위 | 서버별로 따로 셉니다 (소원권과 같습니다) |

### 오늘 이미 올렸다면

명령을 다시 쓰면 막히지만, **「그래도 계속」** 버튼이 함께 나옵니다.
누르면 방금 적은 글자로 하나 더 올라갑니다 — 다만 **출헉으로 세지 않습니다.**

```
┌ (파랑) ──────────────────────────────────────
│ ### 출헉 (기록 안 됨)         ← 제목으로 분명히 합니다
│ ┌──────────────────────────┐
│ │  한번더                    │
│ └──────────────────────────┘
│ ─────────────────────────────────────────────
│ [ 안녕난버튼이야 ]
└─────────────────────────────────────────────
```

맞혀도 `맞혔습니다 (기록 안 됨)` 로만 나가고 누적·연속·조각은 그대로입니다.

덤은 id 로 구분해 버튼에 싣고, 글자는 저장소에 둡니다 — **글자를 `customId` 에 실을 수는
없습니다. 그게 곧 정답이고 `customId` 는 누구나 볼 수 있습니다.** 지난 날 덤은 다음에
올릴 때 치웁니다.

### 왜 이미지인가

글자를 본문에 적으면 드래그해서 그대로 붙여 넣으면 그만입니다. 받아쓰기가 아니게 됩니다.

그래서 [image.ts](src/attendance/image.ts) 가 글자를 PNG 로 그립니다 —
배경에 잡선을 깔고 글자를 하나씩 조금씩 기울여 놓습니다. 사람은 읽을 수 있고,
화면에서 긁어 갈 수는 없습니다. 같은 글자라도 매번 다르게 그려집니다.

> **여기에만 `@napi-rs/canvas` 를 씁니다.** Node 에는 글자를 그림으로 그리는 기능이 없습니다.
> 미리 빌드된 패키지라 설치 도구가 따로 필요하지 않습니다.
>
> 글자 모양은 **시스템에 깔린 폰트**를 씁니다. 윈도우에는 맑은 고딕이 있어 그대로 되지만,
> 리눅스 서버에는 한글 폰트가 없을 수 있습니다. 그러면 네모(두부)로 그려지므로 봇이 시작할 때
> 로그로 알려 줍니다 — `apt install fonts-noto-cjk` 로 설치하면 됩니다.

### 어제 버튼은 안 눌립니다

버튼에는 아무 상태도 싣지 않고, 누를 때마다 저장된 「오늘의 출헉」을 다시 읽습니다.
그래서 어제 메시지의 버튼을 눌러도 오늘 것으로 판정되지 않습니다.
봇을 껐다 켜도 버튼은 그대로 동작합니다.

**정답은 모달에 싣지 않습니다.** 모달 내용은 클라이언트가 전부 볼 수 있습니다.

**버튼을 연타해도 하루는 하루입니다** — 읽고·고치고·쓰기가 한 번의 저장 안에서 일어납니다.

## 소원권 시스템

소원권과 소원권 조각을 관리하고, 소원을 신청/승인하는 시스템입니다. 데이터는 서버(길드)별로 나뉩니다.

- **소원권 조각 N개 → 소원권 1장** — N 은 서버마다 정합니다 (관리자 패널 > 설정, 기본 5, 1~100)
- **소원권 1장 → 소원 1건**
- 수량이 음수가 되는 변경은 **적용되지 않고** 부족 안내가 나갑니다.

### 명령어

```
/소원권 패널
```

**권한을 보고 알아서 엽니다.** 관리자는 관리자 패널이, 나머지는 유저 패널이 열립니다.

관리자에게는 제목 **오른쪽 끝**에 전환 버튼이 붙습니다. 누르면 두 패널을 오갑니다.

```
┌ (파랑) ──────────────────────────────────────
│ ### 소원권 · 유저 패널          [ 관리자 패널 ]  ← 관리자에게만
│ **확인** — 내 보유 수량과 …
│ …
│ ─────────────────────────────────────────────
│ [확인] [랭킹] [제작] [사용] [낭비]
│ ─────────────────────────────────────────────
│ -# @사용자명
└─────────────────────────────────────────────
```

- 일반 유저에게는 버튼이 **아예 보이지 않습니다** — 눌러도 막히는 문을 두드리게 하지 않습니다
- 버튼을 눌렀을 때도 권한을 **다시 확인합니다**. `customId` 는 누구나 흉내 낼 수 있습니다
- 동작을 하고 난 결과 화면에도 전환 버튼이 그대로 남습니다

패널은 누른 사람에게만 보입니다(ephemeral). 모든 버튼과 셀렉트는 컨테이너 안에 들어 있고,
동작 후에도 패널 버튼이 그대로 남아 이어서 쓸 수 있습니다.

### 공개 결과 메시지

패널은 누른 사람에게만 보이므로 결과가 채널에 남지 않습니다. 그래서 결과를 채널에도 공개로 남깁니다.
공개 방식은 두 가지입니다.

**① 기록만 남기기** — 제작 · 낭비 · 수수 · 흡혈

패널은 결과 화면으로 바뀌고, 같은 내용이 채널에 **버튼 없는 컨테이너**로 한 번 더 올라갑니다.
버튼을 그대로 두면 지나가던 사람이 눌러 **자기 계정으로** 제작·낭비가 실행되기 때문에 떼어 냅니다.

**② 조작까지 공개** — 확인 · 랭킹

패널은 **그대로 두고**, 드롭다운·페이지 버튼을 그대로 실은 화면을 채널에 공개로 띄웁니다.
이후 조작은 그 공개 메시지를 갱신하므로 페이지를 넘겨도 메시지가 쌓이지 않습니다.
읽기 전용이라 다른 사람이 조회해도 안전합니다.

```
패널 [랭킹] 클릭
  └ 패널은 그대로, 채널에 공개 랭킹 메시지 생성
       [랭킹 기준 ▼]
       [이전] [1/3] [다음]     ← 누르면 이 메시지가 갱신됨
```

| 동작 | 공개 |
|------|------|
| 확인 · 랭킹 | ✅ 드롭다운·버튼째 공개, 조작은 그 메시지를 갱신 |
| 제작 · 낭비 · 수수 · 흡혈 | ✅ 버튼 없는 컨테이너로 기록 |
| **사용** | ❌ 이미 소원 전달 채널로 따로 감 |
| **설정** | ❌ 서버 설정이라 공개하지 않음 |
| 권한 없음 · 입력값 오류 | ❌ 누른 사람에게만 |

**유저 패널**

| 버튼 | 동작 |
|------|------|
| 확인 | 내 보유량. 드롭다운으로 다른 유저의 보유량도 조회 |
| 랭킹 | 10명씩 페이지. 드롭다운으로 소원권/조각 기준 전환, 이전/다음 버튼. **기준 항목만 표기하고, 그 항목이 0인 사람은 명단에서 뺍니다** |
| 제작 | 조각 5개 → 소원권 1장 |
| 사용 | 모달(소원 내용 + 첨부파일) → 관리자 채널로 전달 |
| 낭비 | 모달(드롭다운으로 소원권/조각 선택) → 1개 소멸, 출력은 `🤸` |

**관리자 패널** (관리자 권한 필요 — 패널을 열 때와 버튼을 누를 때 모두 확인)

| 버튼 | 동작 |
|------|------|
| 수수 | 모달 4항목: 지급/회수 · 소원권/조각 · 대상 유저(여러 명) · 갯수 |
| 흡혈 | 모달 4항목: 소원권/조각 · 흡혈**될** 유저 · 흡혈**할** 유저 · 갯수 |
| 설정 | 소원 전달 채널 + 제작 비용(조각 몇 개로 소원권 1장) |

**설정 모달**은 현재 값을 미리 채워서 띄웁니다. 채널은 **선택 항목**이라 비워 두면 그대로 유지되므로,
제작 비용만 바꾸고 싶을 때 채널을 다시 고를 필요가 없습니다.

제작 비용을 바꾸면 제작 · 확인의 "제작 가능" · 패널 안내문이 모두 그 값을 따릅니다.
저장 파일에 이 항목이 없던 기존 서버는 자동으로 기본값 5가 적용됩니다.

**흡혈** 은 한 사람에게서 빼서 다른 사람에게 옮깁니다. 먼저 빼고, 성공했을 때만 더합니다 —
빼앗길 사람의 보유량이 모자라면 `applyBalanceChange` 가 아무것도 바꾸지 않고 실패를 돌려주므로
**어느 쪽도 변하지 않습니다.** 결과에는 두 사람의 변동 문구가 모두 표시됩니다.

```
흡혈
소원권 조각 3개 · @빼앗긴사람 → @가져간사람

@빼앗긴사람
소원권 조각: 4개 → 1개

@가져간사람
소원권 조각: 0개 → 3개
```

같은 사람을 양쪽에 고르면 거부합니다.

### 소원 흐름

```
유저: 사용 → 모달 제출
  └ 소원권 1장 차감 → 소원 기록 생성 → 설정된 채널에 전달
        └ 채널 전송 실패 시 차감을 되돌리고 기록 삭제

관리자: 전달된 메시지의 [수락] / [거절]
  ├ 원본은 내용 그대로 — 색만 결과 색(초록/빨강), 버튼만 비활성 「수락됨 / 거절됨」
  ├ 결과(신청자·처리한 관리자·환불 변동)는 그 메시지에 **답글**로 달림
  ├ 거절이면 소원권 1장 환불 + 변동 문구 표기
  └ 두 경우 모두 신청자에게 DM 으로 알림 (DM 이 막혀 있으면 조용히 넘어감)
```

> **결과를 원본에 덮어쓰지 않는 이유**: 이미지와 첨부가 원본에 붙어 있습니다.
> 결과 내용으로 원본을 갈아 끼우면 그게 날아갑니다. 그래서 원본은 색과 버튼만 바꾸고,
> 결과는 답글로 남깁니다.

동시에 두 관리자가 눌러도 한 번만 반영됩니다 — 상태 확인과 변경이 한 트랜잭션 안에서 일어납니다.

**봇을 껐다 켜도 수락/거절 버튼은 그대로 동작합니다.** 소원 기록은 `data/wishes.json` 에 있고,
버튼은 `wish:accept:<소원 id>` 처럼 필요한 정보를 `customId` 에 싣고 있으며, 핸들러는 부팅할 때
다시 등록되기 때문입니다. 메모리에 들고 있는 상태가 없습니다.

### 첨부파일

모달로 올라온 파일은 **임시 업로드**라서 그 URL 을 그대로 두면 나중에 만료됩니다.
그래서 소원을 채널에 올릴 때 봇 메시지에 **다시 첨부**해 영구 파일로 만듭니다.

컨테이너 안에서 이미지는 **묶음(`MediaGallery`)** 으로, 이미지가 아닌 파일은 **`File` 카드**로
나뉘어 그려집니다 ([galleryImages / galleryFiles](src/wish/attachments.ts)).

```
│ ───────────────────
│ [🖼️ a.png] [🖼️ b.png]   ← MediaGallery — 최대 10장, 한 묶음
│ [📄 문서.pdf · 3.3MB]     ← File 컴포넌트
```

둘 다 **`attachment://<파일명>`** 으로 가리킵니다. Components V2 메시지에서는 **컴포넌트가 가리킨
첨부만** 그려지므로, 임베드 시절처럼 같은 이미지가 첨부로 한 번 · 미리보기로 한 번 두 벌로
보이는 일이 없습니다.

파일명은 메시지를 보낸 뒤 **메시지에서 직접 읽어** 저장합니다(`fromMessage`) — 임시 업로드 URL 을
영구 URL 로 갈아 두기 위해서입니다.

> **메시지를 수정할 때는 남길 첨부를 반드시 다시 넘기세요.** `attachment://` 참조는 그 요청의
> 첨부 목록을 기준으로 풀립니다. 아무것도 안 넘기면 참조가 깨져 이미지와 파일이 함께 사라집니다.
>
> [`retained(message)`](src/wish/attachments.ts) 가 원래 붙어 있던 첨부를 id 그대로 돌려주고,
> 수락/거절은 그것을 `attachments` 에 실어 보냅니다. 새로 업로드하지 않고 유지만 합니다.

### 수량 변경은 한 곳에서만

지급 · 회수 · 제작 · 사용 · 낭비 · 환불이 전부 같은 함수를 지납니다. 부호와 항목만 다릅니다.

```ts
// src/wish/store.ts
applyBalanceChanges(guildId, userIds, delta)   // 여러 명
applyBalanceChange(guildId, userId, delta)     // 한 명 (위 함수를 감싼 것)
```

| 상황 | delta |
|------|-------|
| 지급 3장 | `{ tickets: 3 }` |
| 회수 2개 | `{ fragments: -2 }` |
| 제작 | `{ fragments: -5, tickets: 1 }` |
| 사용 · 낭비 | `{ tickets: -1 }` |
| 거절 환불 | `{ tickets: 1 }` |

반환값은 `{ ok: true, before, after }` 또는 `{ ok: false, reason: "insufficient", before }` 입니다.
여러 명을 한 번에 처리할 때 일부만 실패할 수 있고, 실패한 사람은 **아무것도 바뀌지 않습니다.**

### 데이터 저장

`data/wishes.json` 한 파일에 서버별로 저장됩니다(gitignore 됨).
임시 파일에 쓴 뒤 `rename` 하므로 저장 중에 프로세스가 죽어도 파일이 깨지지 않고,
쓰기는 큐로 직렬화되어 읽고-고치고-쓰는 사이에 다른 요청이 끼어들 수 없습니다.

```
data/wishes.json
└ guilds
  └ <서버 ID>
    ├ balances  { <유저 ID>: { tickets, fragments } }
    ├ settings  { wishChannelId }
    └ wishes    { <소원 ID>: { userId, content, attachments, status, … } }
```

백업은 이 파일 하나만 복사하면 됩니다.

## 컴포넌트(버튼·셀렉트·모달) 응답 처리하기

버튼을 눌렀는데 아무 응답이 없으면 디스코드가 「이 인터랙션에 실패했습니다」를 띄웁니다.
그래서 `customId` 앞부분을 네임스페이스로 삼아 핸들러를 찾는 라우터를 씁니다.

```
customId:  demo:counter:3
           └┬─┘ └───┬──┘
    네임스페이스   args (핸들러가 받는 값)
```

`src/components/` 에 파일을 만들고 `defineComponentHandler` 를 default export 하면 등록됩니다.

```ts
// src/components/vote.ts
import { MessageFlags } from "discord.js";

import { defineComponentHandler } from "../types.js";

export default defineComponentHandler({
  namespace: "vote",
  async execute(interaction, args) {
    if (!interaction.isButton()) return;

    await interaction.reply({
      content: `${args[0]} 에 투표했습니다.`,
      flags: MessageFlags.Ephemeral,
    });
  },
});
```

버튼 쪽에서는 `customId("vote", "yes")` 로 `vote:yes` 를 만들면 됩니다.

> 흔히 쓰는 `awaitMessageComponent`(컬렉터)와 달리, 이 방식은 봇이 켜져 있는 한 계속 동작합니다.
> 대신 봇을 재시작하면 이전 메시지의 버튼은 핸들러를 못 찾으니, 상태가 필요하면 `customId` 에 실어 두세요
> (랭킹의 이전/다음 버튼이 페이지 번호를 `customId` 에 실어 두는 방식입니다).

## 주의할 점 두 가지

**1. 인텐트** — [src/client.ts](src/client.ts) 에서 관리합니다.
지금은 `Guilds` · `GuildMembers` · `GuildMessages` 를 씁니다.

> ⚠️ **`GuildMembers` 는 특권 인텐트입니다.** `/별명` 이 서버 전원의 목록을 받아오는 데 필요합니다.
> Developer Portal → 앱 선택 → **Bot** → *Privileged Gateway Intents* → **Server Members Intent** 를
> 켜 주세요. 켜지 않으면 봇이 **로그인 자체를 못 하고** `Used disallowed intents` 로 죽습니다.

`GuildPresences` 와 `MessageContent` 도 특권 인텐트입니다. 필요해지면 같은 방식으로 켜고 추가하세요.

**2. import 확장자** — ESM 프로젝트라서 상대 경로 import 에는 `.js` 를 붙입니다.
소스 파일이 `types.ts` 여도 `import { defineCommand } from "../types.js";` 가 맞습니다
(빌드 후 실제로 `.js` 가 되기 때문). 확장자를 빼면 실행 시 `ERR_MODULE_NOT_FOUND` 가 납니다.

## 문제가 생기면

| 증상 | 원인 |
|------|------|
| `환경변수 DISCORD_TOKEN 가 비어 있습니다` | `.env` 가 없거나 값이 빔 |
| `An invalid token was provided` | 토큰 오타. Client Secret 이 아니라 **Bot 토큰**이 맞는지 확인 |
| `401: Unauthorized` (deploy) | 토큰이 틀렸거나 `DISCORD_CLIENT_ID` 가 다른 앱의 ID |
| 서버에서 커맨드가 안 보임 | `npm run deploy` 안 함 / 초대 시 `applications.commands` 스코프 누락 / 글로벌 등록 반영 대기 |
| 버튼 누르면 「이 인터랙션에 실패했습니다」 | 3초 안에 응답하지 않았거나, `customId` 네임스페이스에 맞는 핸들러가 없음. 봇 재시작 전에 보낸 메시지의 버튼일 수도 있음 |
| 모달이 안 뜸 | `showModal()` 은 첫 응답으로만 됩니다. 이미 `reply()`/`deferReply()` 했으면 못 띄웁니다 |
| Components V2 메시지가 400 에러 | `MessageFlags.IsComponentsV2` 를 켠 메시지에는 `content`/`embeds` 를 같이 못 씁니다. 렌더러를 거치면 이 조합이 나올 수 없습니다 |
| 옛 메시지 갱신이 400 에러 | 임베드로 만든 메시지는 컨테이너로 바꿀 수 없습니다(그 반대도). `message.flags.has(IsComponentsV2)` 로 갈라서 처리하세요 |
| `COMPONENT_CUSTOM_ID_DUPLICATED` | 한 메시지 안에 같은 `customId` 가 두 번. 비활성 버튼도 검사 대상입니다 — 페이지네이션에서 이전/다음 목표 페이지를 범위로 깎으면 같아질 수 있으니 깎지 마세요 |
| 메시지를 수정하니 첨부파일이 사라짐 | 남길 첨부를 다시 넘기지 않아 `attachment://` 참조가 풀린 것. [`retained(message)`](src/wish/attachments.ts) 를 `attachments` 에 실으세요 |
| 「소원을 빌 수 없습니다」 | 관리자 패널 > 설정 에서 전달 채널을 먼저 지정해야 합니다 |
| 소원이 채널로 안 감 | 봇이 그 채널에 **메시지 보내기** 권한이 있는지 확인 (실패하면 소원권은 자동 환불됩니다) |
| `Used disallowed intents` | 위 "주의할 점 1" 참고 |
| `ERR_MODULE_NOT_FOUND` | import 에 `.js` 확장자 누락 |

## 배포

```bash
npm run build
npm start
```

`dist/` 와 `node_modules/`, `.env` 가 있으면 실행됩니다. `SIGINT`/`SIGTERM` 을 받으면 게이트웨이 연결을 정리하고 종료하므로 프로세스 매니저와 함께 쓰기 좋습니다.

윈도우에서는 **`run.bat` 을 더블클릭**하면 Node 확인 · `.env` 준비 · 패키지 설치 · 실행을 한 번에 처리합니다.
릴리스 zip 에도 함께 들어갑니다 — 자세한 내용은 [RELEASE.md](RELEASE.md#릴리스에-담기는-것) 참고.

데이터는 실행 위치 기준 `data/` 아래에 쌓입니다
(`wishes.json` · `nicknames.json` · `timeouts.json` · `tasalbeo.json` · `attendance.json`).
봇을 옮길 때는 이 폴더도 함께 옮기세요 — 타살버의 **걸기 전 별명**도 여기 들어 있습니다.
